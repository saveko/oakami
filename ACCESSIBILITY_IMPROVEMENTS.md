### 3. Global CSS Accessibility Improvements
**File:** `/apps/frontend/src/styles/globals.css`

- **Focus Management:**
  - 2px outline with 2px offset for all interactive elements
  - Dedicated focus-visible states for keyboard navigation
  - Screen reader text utility class (.sr-only)

- **Motion Accessibility:**
  - Respects `prefers-reduced-motion` media query
  - Disables animations for users with motion sensitivity
  - Fallback to instant state changes (0.01ms)

- **Typography:**
  - Base font size: 16px (clear, readable)
  - Line height: 1.5 (improved readability)
  - Font family: -apple-system stack with Fira Sans/Code fallbacks

- **Touch Targets:**
  - Minimum button size: 44x44px
  - Proper spacing between interactive elements

- **Color Variables:**
  - Semantic color tokens (primary, secondary, accent, destructive)
  - CSS custom properties for dynamic theming
  - Dark mode support built-in

## Accessibility Standards Met

### WCAG 2.1 Compliance
- **Level AA:** All interactive components
- **Contrast Ratio:** 4.5:1 minimum (text), 3:1 minimum (large text)
- **Focus Indicators:** Visible on all interactive elements
- **Keyboard Navigation:** Full support for Tab, Enter, Space, ESC
- **Screen Reader Support:** Proper ARIA labels, roles, and landmarks

### Mobile Accessibility
- **Touch Targets:** 44x44px minimum for all buttons
- **Spacing:** 8px+ gaps between interactive elements
- **Responsive:** Supports 375px, 768px, 1024px, 1440px breakpoints
- **No Horizontal Scroll:** All content reflows vertically

### Cognitive Accessibility
- **Clear Language:** Simple, direct form labels and instructions
- **Progressive Disclosure:** Conditional fields only shown when relevant
- **Error Clarity:** Specific, actionable error messages
- **Visual Feedback:** Loading states, success messages, validation indicators

## Design System Integration

### Using the Design System
1. **Master Rules:** Read `/design-system/oakami/MASTER.md` for global guidelines
2. **Page Overrides:** Check `/design-system/oakami/pages/[page].md` for specific rules
3. **Color Tokens:** Use Tailwind color names from config (primary, accent, destructive)
4. **Typography:** Use Fira Code for data/headings, Fira Sans for body text
5. **Spacing:** Follow 8px grid (8, 16, 24, 32px multiples)
6. **Motion:** Keep animations 150-300ms, respect prefers-reduced-motion

### Pre-Delivery Checklist (per Design System)
- [ ] No emojis as icons (use SVG)
- [ ] `cursor-pointer` on clickable elements
- [ ] Hover states with 150-300ms transitions
- [ ] Text contrast 4.5:1 minimum (light mode)
- [ ] Focus states visible for keyboard nav
- [ ] `prefers-reduced-motion` respected
- [ ] Responsive at 375px, 768px, 1024px, 1440px

## Performance Improvements

### Frontend Bundle
- Design system tokens reduced inline styles
- Google Fonts lazy-loaded (Fira Code/Sans)
- Utility classes centralized in globals.css

### Rendering
- CSS variables enable theme switching without re-renders
- Focus styles use outline (no box-shadow for performance)
- Tailwind optimizations through config extensions

```bash
# Screen reader testing
# Use built-in screen reader (VoiceOver, Narrator, NVDA)

# Mobile testing
# Test on 375px, 768px, 1024px breakpoints
```

### Key Test Scenarios
1. **Waste Approval:** Tab through form → Fill fields → Approve/Reject buttons
2. **Report Schedule:** Create schedule → Verify progressive disclosure → Submit
3. **Notifications:** Open bell → Mark as read → Close with ESC
4. **Dark Mode:** Enable system dark mode → Verify contrast
5. **Reduced Motion:** Enable prefers-reduced-motion → Verify no animations
